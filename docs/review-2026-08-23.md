# Life OS — Product & Technical Review

Date: 2026-08-23

## What is working

- The Hearth has a clear emotional purpose and a deliberately minimal UI direction.
- Arrival states route into different kinds of questions.
- Questions support both text and multiple-choice responses.
- Reflections can be saved without automatically becoming stars.
- Stars are explicitly chosen by the user.
- Remembrance is a first-class path, including a no-words lantern action.
- The Night Sky supports drag and pinch/zoom.
- Local data is preserved across refreshes and older prototype data is migrated forward.
- The app is installable as a static PWA and deployable via GitHub Pages.
- Reduced-motion and keyboard focus states are now present.

## P0 — Before trusting the app with important personal history

### 1. Data durability
Current storage is local browser storage. Clearing site data, browser reset, or device loss can erase entries.

Needed:
- restore/import from backup
- automatic backup strategy
- eventually secure sync across devices

### 2. Privacy/security model
The product contains intimate reflections, but there is no encryption, authentication, device lock, or explicit privacy model yet.

Needed before broad use:
- threat model
- encrypted-at-rest design for synced data
- account/session approach or a consciously account-free local mode
- clear user control over deletion/export

### 3. Edit/delete controls
Saved entries currently cannot be edited or deleted from the UI.

Needed:
- edit reflection
- delete reflection
- add/remove star status independently
- confirmation that remains calm and reversible where possible

### 4. Data schema stabilization
The prototype has now moved from duplicated star objects to normalized `entries` + `stars` references. Future schema changes should use explicit migrations and tests.

## P1 — Core product gaps

### 5. Question Engine is still shallow
Current adaptation is based on arrival, affinity feedback, depth, and recency. It does not yet understand themes in answers or user-confirmed patterns.

Needed:
- cooldown rules by question
- deeper-question trust threshold
- avoid-when rules
- question history
- user-confirmed pattern memory
- ability to say “never ask this again”

### 6. Multiple-choice needs nuance
Choice questions are useful for low cognitive load, but some will need:
- multi-select
- “something else”
- optional follow-up text
- no forced interpretation of one-tap answers

### 7. Constellations are theme buckets, not true constellations yet
Current lines are grouped by question intent. That is a placeholder, not a meaningful pattern model.

Needed:
- user-created constellation names
- accept/reject/redraw suggested connections
- a star may belong to zero, one, or multiple constellations
- zoom-level behavior: years → constellations → stars
- avoid treating frequency as importance

### 8. Remembrance is incomplete
Needed:
- people/animal memorial records
- birthdays and loss anniversaries entered by the user
- Memory Gardens
- stories/photos/voice notes
- ability to choose whether dates prompt anything at all

### 9. No daily rhythm yet
There is no distinction between morning, evening, weekly, or seasonal reflection beyond labels.

Needed:
- optional time-of-day question pools
- user-controlled prompting cadence
- silence as a valid experience

## P2 — Experience and quality

### 10. Accessibility needs a proper audit
Current improvements include focus-visible and reduced motion, but still needed:
- screen-reader pass
- dialog focus trap + Escape handling
- color-contrast verification
- dynamic type/text scaling checks
- touch target review
- semantic heading review

### 11. Offline behavior needs testing
The service worker is simple and should be tested on real iOS install/update flows, especially stale-cache behavior.

### 12. App icon/install experience
A basic SVG icon exists, but iOS home-screen artwork and maskable PNG assets should be added later.

### 13. No tests
There are currently no automated tests.

Highest-value first tests:
- data migration preserves old entries/stars
- save vs save-as-star behavior
- question selection respects intent/state
- star references cannot orphan silently

### 14. Code architecture is still prototype-scale
The refactor separates questions, storage/migrations, and UI logic, but `app.js` still contains all screens and interactions.

Next sensible split when features grow:
- `screens/`
- `sky/`
- `question-engine/`
- `components/`

Do not introduce framework complexity until the product behavior warrants it.

## Product principles reaffirmed

- Calm comes from restraint, not copy explaining calmness.
- Not every answer needs a follow-up.
- Not every saved reflection is a star.
- Stars are chosen by the user.
- Pattern recognition should propose, not define.
- The app should learn without becoming cognitively demanding.
